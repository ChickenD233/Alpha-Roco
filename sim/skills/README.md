# 技能系统规范（sim/skills）

> 本文只规定技能系统的**规则与边界**。条款前缀 `S`。
> 通用写作与续写标准见 `SPEC.md` 第 12 节；跨系统规则不在此复述。

## 1. 总则

- **S1** 技能效果**一律以代码定义**并按技能 ID 注册，不得写进 `data/skills.json`。
- **S2** 技能描述不得被解析（`SPEC.md` D2）：正则、关键词匹配、自定义迷你语言在本项目中一律禁止。
- **S3** 条件式效果（"若先手"、"敌方每有 1 层中毒"、"若敌方本回合更换精灵"）必须用条件表达，不得退化为文本匹配。
- **S4** 未实现的技能一律是 no-op 占位：不产生效果、不写日志、不报错。注册表必须始终覆盖**全部**技能，分发不得缺项。
- **S5** 结构与特性系统同构：上下文与基类 / 注册表 / 按类别分文件的实现 / 顶层进度报告。

## 2. 分类与规模

| 类别 | 含义     | 条数 |
| ---: | -------- | ---: |
|    0 | 物理攻击 |  190 |
|    1 | 魔法攻击 |  155 |
|    2 | 防御     |   52 |
|    3 | 状态     |  157 |

合计 554 条；类别 `0` / `1` 统称攻击类。

## 3. 进度与自检规范

- **S6** 进度以 `data/skills.json` 的 `done` / `tested` 标志为准：`done` = 全部效果已定义；`tested` = 已逐个核验。文档不记录数字。
- **S7** 自检必须报出两件事：**覆盖率**（总数 / done / tested）与**一致性**（handler 的名称与类别必须与技能数据一致，且不得存在技能数据中不存在的技能 ID）。效果定义与数据一旦漂移必须立即报出。**边界**：负数技能 ID 是运行时虚拟技能（愿力冲击等特性/共鸣替换用），不属于 `skills.json`，一致性检查跳过。

## 4. 阶段规范

- **S8** 引擎只在下列时机进入技能阶段；未列出的时机不得触发技能效果。

| 阶段                | 触发时机                                            | 该阶段允许的效果                                          |
| ------------------- | --------------------------------------------------- | --------------------------------------------------------- |
| `STAGE_ENTRY`       | 精灵入场结算时，对其携带的每个技能                  | 入场成长（"每次入场，本技能威力永久+40"）                 |
| `STAGE_SLOT_CHANGE` | 传动重排后，槽位发生变化的技能                      | 位置变化成长（"每回合位置发生变化时，本技能威力永久+15"） |
| `STAGE_USE_START`   | 支付能耗后、造成伤害前                              | 附加状态、驱散、改变属性                                  |
| *（无阶段）*        | 伤害计算中                                          | 只通过第 6 节的查询参与（威力 / 连击 / 吸血）             |
| `STAGE_HIT`         | 技能命中后立即结算                                  | 命中附加、自回血回能                                      |
| `STAGE_COUNTER`     | 应对判定成功后的回合末结算（第一步，`SPEC.md` B38） | 应对奖励                                                  |
| `STAGE_DEFENSE`     | 防御技能本体                                        | 减伤、脱离                                                |
| `STAGE_STATUS`      | 状态技能本体                                        | 施加印记、加增益、回能                                    |
| `STAGE_AFTER_USE`   | 使用后、技能结束前                                  | 永久成长、替换、位置变化、冷却、脱离                      |
| `STAGE_ROUND_END`   | 回合结束                                            | 持续效果的回收与结算                                      |

- **S9** `STAGE_HIT` 在"本次伤害结算后"立即执行，**包含未造成伤害的情形**；脱离/返场请求也在本次行动后立即处理。
- **S10** `STAGE_COUNTER` 仅在应对判定成功时触发；未成功时应对奖励一律不执行。
- **S11** 脱离、返场只**登记请求**，不得在效果执行中途换人；实际执行时机由引擎决定。打断不是登记请求，而是第 5 节的静态属性，在行动排序时立即生效（`SPEC.md` B40）。
- **S12** `STAGE_ROUND_END` 对在场且存活精灵携带的技能结算持续效果。
- **S12a** `STAGE_ENTRY` 在入场结算时对入场精灵的**每个**携带技能广播一次（含开局首发、主动换人、被动换人、力竭替补、返场）。当前无"是否需要"的筛选，未声明入场效果的技能不受影响。
- **S12b** `STAGE_SLOT_CHANGE` 只在传动重排后、对**槽位确实改变**的在场技能触发，`ctx.extra` 给出 `old_index` / `new_index`（0-based）。覆盖开局排序、回合末重排、换人后的重排；场下精灵不参与传动重排，因此不触发。位置未变时不触发。
- **S13** 静态属性绑定是**构造期**行为，此时没有战斗状态；绑定只能写入静态字段。
- **S14** 阶段是否已接入引擎以第 10 节的未接入清单为准；清单之外的阶段均已接入。

## 5. 静态属性规范

| 属性     | 含义                                                     | 边界                |
| -------- | -------------------------------------------------------- | ------------------- |
| 应对类别 | `攻击` / `防御` / `状态`                                 | 空 = 不应对         |
| 打断     | 应对成功时立即作废被应对的技能/聚能行动（`SPEC.md` B40） | 默认否              |
| 传动     | 传动值                                                   | 默认 `0`            |
| 迅捷     | 主动换人入场时自动释放                                   | 默认否              |
| 蓄力     | 需先蓄力 1 回合                                          | 默认否              |
| 可用性   | 否 = 无法主动使用                                        | 默认是              |
| 固有属性 | 改写本技能的属性                                         | 空 = 用数据里的属性 |
| 巧变池   | 运行时替换的候选技能池                                   | 空 = 不巧变         |
| 选择     | 含「明/暗」两个效果，使用时二选一                        | 默认否              |

- **S15** 技能描述自带的静态属性写在技能侧；特性赋予的静态属性由特性侧写入（`SPEC.md` P9 / P10）。
- **S15a** 选择的输入通道是 `Action.choice_branch`（0=明，1=暗）；服务端把它写进本次行动，引擎在每个结算阶段的 `SkillContext.choice_branch` 上透传给技能 handler。引擎只提供分支值，不代填任何效果——明/暗的具体内容由 skills/ 的 handler 读取 `ctx.choice_branch` 后自行填写。

## 6. 修正查询规范

- **S16** 本系统全部查询遵守 `SPEC.md` P11 的增量语义约定。

| 查询                     | 返回值                           | 边界                                                                                                                                                                                          |
| ------------------------ | -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `query_power`            | 百分比增量、固定值增量           | —                                                                                                                                                                                             |
| `query_absolute_power`   | 整数或空                         | 对基础威力**绝对值覆盖**；优先于增量                                                                                                                                                          |
| `query_hit_count`        | 固定增量、百分比增量、强制值或空 | 强制值非空时忽略增量                                                                                                                                                                          |
| `compute_hit_count`      | 总连击数（整数）                 | 基础 1 + buff + 特性 + 技能自身 `modify_hit_count`，攻击/状态连击技能共用；状态技能用它做 `Repeat` 次数；技能固有连击数（"N连击"）用 `modify_hit_count`/`hit_count_flat` 给出增量，不另设字段 |
| `query_energy_cost`      | 整数增量                         | —                                                                                                                                                                                             |
| `query_priority`         | 整数增量                         | 行动排序：应对强制先手之下、有效速度之上（`SPEC.md` B10）                                                                                                                                     |
| `query_lifesteal`        | 比例增量                         | —                                                                                                                                                                                             |
| `query_damage_reduction` | 比例                             | 替代文本解析；引擎必须钳制到 `[0, 1]`（`SPEC.md` B25）                                                                                                                                        |
| `query_element`          | 属性编号                         | 改写本技能属性                                                                                                                                                                                |

- **S17** 由规则算出威力的技能必须走绝对覆盖，数据里只放桩值；不得把增量折算成百分比去乘桩值（`SPEC.md` D6）。

## 7. 可表达的效果范围

### 7.1 作用对象

自己 / 对方在场精灵 / 己方场下 / 己方全员 / 对方全员 / 双方在场。

### 7.2 效果原语

| 分组   | 原语                                                                                                                                                                                                                                                         |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 能量   | 回复能量（含上限）、失去能量、偷取能量、能量不足时以生命代替能量                                                                                                                                                                                             |
| 生命   | 回复生命、失去生命（代价类）                                                                                                                                                                                                                                 |
| 增减益 | 施加增益/减益（负值即减益）、随机 N 层属性增益（双攻双防与速度，按属性汇总施加）、按元素的技能威力增益（`power_boost_<元素id>`）、驱散增益/减益、增益转同层数中毒、减益层数翻倍、双方增减益互换；施加萌化时广播自动携带 `pre_had`，能够获得萌化的条件与萌化威力加成遵守统一获得判定（含特性文档 T31 的例外） |
| 印记   | 添加印记、驱散或偷取印记（驱散可覆盖双方阵营，并可把总层数记录给同组后续效果）、buff 层数转同侧印记                                                                                                                                                          |
| 伤害   | 附加伤害（可指定属性、类别、连击数）                                                                                                                                                                                                                         |
| 场上   | 改变天气、设置技能冷却、脱离、返场                                                                                                                                                                                                                           |
| 成长   | 本技能永久成长（威力 / 能耗 / 连击）、使用次数 +1、给予迸发                                                                                                                                                                                                  |
| 控制   | 条件门、重复执行子效果（连击类）、重放使用过的迅捷技能（引擎级：免费、按槽位顺序、无应对效果、基础结算）、选择（占位原语；明/暗效果由 handler 按 `ctx.choice_branch` 填写）、奉献（队伍级资源，S32）                                                                                                                                    |

- **S26** 驱散增益/减益的判据有两条，互相独立：①**是不是增益/减益**只看效果类型与数值，**与时长无关**——常规时长与永久时长的增益/减益同样会被驱散；②**特性自身的展示效果**（`source_kind="trait"`，`sim/traits/README.md` T17）不是增益也不是减益，属于另一个类别，不参与驱散。特性给敌方施加的减益（`source_kind="debuff"`）照常按减益参与驱散。
- **S27** 驱散指定种数时，可驱散项多于该数则**随机**选取（如"驱散敌方1种增益"）；不超过则全部清除。
- **S28** 重复执行（"N连击，每次连击…"）把子效果独立执行 N 次，每次都独立触发事件——"每次获得X时追加"类特性按次数分别响应；不得合并成一次性施加。
- **S30** 按元素的技能威力增益（"自己获得X系技能威力+N%"）用 `power_boost_<元素id>` 命名约定的 buff 承载：引擎在伤害计算时按技能**实际元素**（含属性改写）把该 buff 值并入威力百分比；按数值正负分增益/减益，参与驱散与增益判定。
- **S31** 按技能的能耗修正（"被应对技能能耗+N"）用 `energy_cost_boost_<技能id>` 命名约定的 buff 承载：引擎能耗计算按技能 id 把该 buff 值并入能耗；正值为减益，参与驱散与减益判定。效果的 buff 类型需在结算时按 `ctx.extra["incoming_skill"]` 动态确定（`BoostCounteredSkillEnergyCost`）。
- **S29** 技能 handler **不得**向战斗日志追加文字（与特性侧 T4 同一约定）：效果只通过状态变化体现；`ctx.log` 保留在接口中但默认不使用。**边界**：引擎自身可以为技能引起的结果写日志（使用 / 伤害 / 脱离 / 力竭等），不在此限。

- **S18** 条件门语义：条件不成立时，门内的效果一律不执行。
- **S19** 选择的原语只是登记占位，不在引擎自动执行（选择分支值的输入通道已就绪，明/暗效果由 handler 自行填写；见第 8 节）。
- **S32** 奉献（`Offering`）向己方队伍添加队伍级资源：`grant` 给出种类时逐种获得 `times` 次，留空时每次在 5 种效果中随机抽取；累加与作用范围见 `SPEC.md` B43，啃咬/虫群用 `offerings.bonus` 读取强化，不自行解析描述。

### 7.3 条件原语

恒真 / 先手 / 后手 / 应对指定类别 / 生命不高于 / 生命不低于 / 敌方本回合换人 / 持有增益 / 持有减益 / 天气属于 / 位于指定技能位 / 能量不高于 / 印记达到层数 / 本次已造成伤害 / 本次使用击败敌方 / 能够获得萌化 / 全部成立 / 任一成立 / 取反。

### 7.4 运行时数值

效果的数值既可以是固定值，也可以按当前状态计算。现成辅助：按目标增益层数、按目标印记层数（指定种类）、按目标印记总层数（正负合计、不限种类）、按目标缺失生命比例（自己或敌方，整数步进）、按敌方力竭数量、按同组效果先前记录的数值（`record_as` / `per_recorded` 配套）。

### 7.5 每回合替换与巧变的边界

- 借用、取念、复写使用独立的 `round_replace_origin` 与 `round_replace_pool`：选定首发及后续入场时抽取，在场时回合末重抽，离场还原。借用不额外降耗，取念与复写额外 -2 能耗。候选池明确排除系统技能「蓄能」（9999999）。使用抽到的技能不会触发巧变的用后还原。
- 真正巧变只使用 `morph_pool` / `morph_origin` 与 `_apply_morph`：原技能用后抽取临时技能（额外 -1 能耗），临时技能用后还原。不受每回合替换的重抽或离场还原影响。
- 两套生命周期不能根据抽到的技能 ID 相互接管：每回合替换抽到巧变技能时不建立巧变池；巧变抽到借用、取念、复写时仍由巧变管理。

## 11. 续写标准

> 通用标准见 `SPEC.md` 第 12 节；本节只列本文特有要求。

- **S22** 新增阶段必须写明触发时机与允许的效果；尚未接入引擎的阶段必须同时列入第 10 节。
- **S23** 新增效果原语或条件原语必须同时登记到第 7 节，并写明语义与边界；只在实现里添加而不同步清单视为未完成。
- **S24** 第 8 节机制的引用条数变化时同步更新；新增未建模机制必须给出"引用它的技能一律暂缓"的边界。
- **S25** 第 6 节查询表的"边界"列必须写明空值语义、是否覆盖、是否需钳制；缺失即视为条款不完整。
